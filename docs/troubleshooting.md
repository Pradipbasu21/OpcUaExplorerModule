# OPC UA Troubleshooting Guide

Common issues encountered when working with OPC UA clients, servers, and web proxies, along with recommended solutions.

---

## 1. Connection Failures

### Issue: `BadCommunicationError` or `BadTimeout`
- **Cause**: The OPC UA Server is unreachable, the endpoint URL is incorrect, or a firewall blocks the OPC TCP port (typically `4840`, `53530`, or custom).
- **Remedy**:
  - Verify server is running: `telnet <host> <port>` or `nc -zv <host> <port>`.
  - Check the endpoint protocol starts with `opc.tcp://`.
  - For local simulation, test with Prosys OPC UA Simulation Server on default port `53530`.

### Issue: `BadSecurityChecksFailed` or `BadCertificateUntrusted`
- **Cause**: The server rejected the client application certificate, or the client rejected the server certificate.
- **Remedy**:
  - Open the server's certificate management tab and move the client certificate from "Rejected" to "Trusted".
  - For development only, disable strict certificate checking in `OpcUaService.cs` (`autoAccept: true`).

---

## 2. Address Space & Browsing Issues

### Issue: `BadNodeIdUnknown`
- **Cause**: The NodeId string format does not match the server's namespace index or identifier type.
- **Remedy**:
  - Verify syntax: `ns=2;s=Device1.Temperature` (string) vs `ns=0;i=84` (numeric).
  - Browse hierarchy first to obtain the exact `nodeId` string generated by the server.

### Issue: Tree View is empty or times out
- **Cause**: Too many child nodes or infinite reference loops.
- **Remedy**:
  - Lower the `maxDepth` query parameter in `/api/OpcUa/browse/hierarchy?maxDepth=2`.

---

## 3. Web & Browser Issues

### Issue: CORS error in browser console (`Access-Control-Allow-Origin`)
- **Cause**: Frontend is served on port 5500 while API runs on port 5000 without CORS enabled.
- **Remedy**:
  - Add CORS middleware to `Program.cs` as outlined in `docs/web-explorer-guide.md`, or host frontend inside `wwwroot/`.
